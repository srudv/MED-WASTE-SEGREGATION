# Data Quality Report — Medical Waste Dataset

**Project:** MED-WASTE-SEGREGATION  
**Issue:** Data Cleaning and Preprocessing — #3  
**Source:** CPCB Annual Report on Biomedical Waste Management, 2023, Annexure-I  
**Dataset scope:** 37 State/UT or reporting-entity records; 23 columns; quantities are kg/day.

## 1. Input and preservation
- Input: `medical_waste.csv` from the repository root.
- The raw CSV is not overwritten. Cleaned output is saved separately to `data/processed/medical_waste_cleaned.csv`.
- The source contains 37 records and 23 fields. No total row was added.

## 2. Missing values and special tokens
- `NIL`: converted to numeric zero, as the source documentation describes NIL as “none”.
- `INP`, `NA`, and empty cells: retained as missing; no imputation is performed.
- Explanatory text in numeric columns is represented as missing in the numeric field and recorded in the audit generated by the notebook.
- Missing does not automatically mean zero.

## 3. Duplicate and invalid-record checks
- Duplicate complete rows are checked; none are silently dropped.
- Serial numbers are checked for uniqueness and completeness.
- State/reporting-entity labels are checked for duplicates.
- Numeric fields are parsed; non-numeric source notes are handled through the audit.

## 4. Label and data-type corrections
- `Telengana` → `Telangana`.
- `J & K` → `Jammu & Kashmir`.
- `Andaman Nicobar` → `Andaman and Nicobar Islands`.
- Spacing in `Daman &Diu and Dadra & Nagar Haveli` is normalized; the combined reporting entity remains combined.
- `state_ut` remains text, `s_no` is an integer, and measurement/count fields are numeric.

## 5. Outlier review
Potential outliers are flagged using the 1.5 × IQR rule. These are review flags only. The data is aggregated by State/UT, so large values may reflect population, facility counts or reporting scale. No observations are removed or capped.

## 6. Encoding and scaling
No categorical encoding or feature scaling is applied. This deliverable is a cleaned analytical table for exploratory analysis, not a model-training matrix. Encoding/scaling should be selected after a target variable and model are defined.

## 7. Validation
The preprocessing module checks that 37 records and 23 columns remain, serial numbers are complete and unique, state labels are unique, numeric fields are numeric, and there are no duplicate complete rows.

## 8. Limitations
- The source is a one-year, state-level aggregate, not hospital-level or item-level data.
- `INP` and `NA` are not defined in the source and remain missing.
- Daman & Diu and Dadra & Nagar Haveli remain one combined source record.
- Source inconsistencies are not “corrected” using unsupported assumptions.
- The dataset has no biomedical-waste colour-category labels and is not image-classifier training data.

## 9. Reproducibility
From the repository root:
```bash
pip install -r requirements.txt
jupyter notebook notebooks/01_data_cleaning.ipynb
```
The notebook reads `medical_waste.csv` from the repository root or `data/raw/medical_waste.csv`, and writes cleaned data and audit/validation outputs under `data/processed/`.
